01

Where we started

The first prompt asked for five things: (1) understand and test the existing SecureDeviceControl repo (Windows Service + WPF desktop + Supabase), (2) build a simple admin dashboard EXE with ID/password login that reads the Snapshots bucket organized by device and date, (3) collapse near-duplicate screenshots into sessions instead of AI analysis — you said “remove AI analysis part, keep it simple, keep in organise format”, (4) deliver two ZIPs (dashboard + agent software) with documentation, harmless to this PC, (5) deploy to 50 PCs with no friction. A Groq key was provided but its account had no vision models, so the final scope uses local perceptual hashing only.

Decisions locked in

  • Dedup = local dHash (64-bit, 9×8 resize, Hamming distance, threshold 8) — no AI, no per-image cost.
  • Snapshot key format: {deviceHash}/{yyyy}/{MM}/{dd}/{yyyyMMdd-HHmmss-fff}.jpg, deviceHash = SHA256(MachineName|email)[0..16] lower-hex.
  • Dashboard = WPF net8.0-windows, self-contained single file, first-run Admin ID + PBKDF2-SHA256 (100k) password, settings in %LocalAppData%\SecureDeviceControlDashboard\settings.json with DPAPI-protected service key.
  • Service is the gatekeeper: registration → acknowledgement → enabled flag → JPEG magic FF D8 … FF D9 + 4 B–8 MB → rate limit → upload to bucket Snapshots. Desktop only captures.

50-PC rollout, step by step

Do A once on the build PC. Do B once per PC (first install only). After every PC runs 1.0.2+, do C from your desk forever.

A — Build PC, once per release

A1 [SUPERSEDED Sep 2026 — do NOT bake secrets anymore] Put only the URL + bucket + public anon key in src\Service\appsettings.json; DB password/service_role go to install-time env/file. Bump <Version> in src\SecureDeviceControl.Service\SecureDeviceControl.Service.csproj.
A2 Build + pack (needs the local SDK path + win-x64 restore): 
$env:DOTNET_EXE="C:\tmp\dotnet\dotnet.exe"
C:\tmp\dotnet\dotnet.exe restore .\SecureDeviceControl.sln -r win-x64
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\publish-release.ps1 -Configuration Release -Runtime win-x64
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-zip.ps1
Get-FileHash .\SecureDeviceControl-Release.zip -Algorithm SHA256
A3 Upload the ZIP to Releases → Draft new release → Attach binaries (bottom drop zone, not “Add file”) as SecureDeviceControl-Release.zip under tag v1.0.4. Copy the .../releases/download/v1.0.4/...zip URL + SHA256.
A4 Push the row (Supabase SQL Editor): 
insert into software_updates (version,download_url,sha256_hash,mandatory,target_machine)
values ('1.0.4','https://github.com/Harsh854-22/DriverBasil/releases/download/v1.0.4/SecureDeviceControl-Release.zip','NEW_SHA256_HERE',true,'ALL');

B — Each target PC, first time only (elevated PowerShell)

B1 Extract the 1.0.3 ZIP, unblock, install, wait, verify pipe: 
Set-Location "C:\Path\To\SecureDeviceControl-Release"
Unblock-File -Path .\*
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-service.ps1
# if legacy "Secure Device Control" exists, add: -MigrateLegacyService
Start-Sleep 10; sc.exe query SecureDeviceControl   # STATE : 4 RUNNING
[System.IO.Directory]::GetFiles("\\.\pipe\") | Select-String SecureDeviceControl.v1
& "C:\Program Files\SecureDeviceControl\SecureDeviceControl.Desktop.exe"
B2 In the desktop: tick “I understand … snapshots every 5 minutes …”, enter a unique Email per PC (one Email = one PC is enforced), two different 6-digit PINs → Initialize & Register. Leave the app in the tray (X hides since 1.0.2).
B3 Old 1.0.0 PCs only — one manual jump (service EXE is locked while running): 
Invoke-WebRequest -Uri "https://github.com/Harsh854-22/DriverBasil/releases/download/v1.0.3/SecureDeviceControl-Release.zip" -OutFile "C:\Temp\SecureDeviceControl-Release.zip"
Stop-Service SecureDeviceControl -Force
Expand-Archive "C:\Temp\SecureDeviceControl-Release.zip" -DestinationPath "C:\Temp\New" -Force
Copy-Item "C:\Temp\New\*" "C:\Program Files\SecureDeviceControl\" -Recurse -Force
Start-Service SecureDeviceControl
(Get-Item "C:\Program Files\SecureDeviceControl\SecureDeviceControl.Service.exe").VersionInfo.FileVersion  # 1.0.3.0
Do not uninstall — in-place copy keeps PINs, email and logs.

C — Every future update, from your desk (no target access)

Repeat A3–A4 only. Each PC’s SoftwareUpdateWorker (LocalSystem, 1-hour poll + on restart) downloads the URL, verifies SHA256, extracts over C:\Program Files\SecureDeviceControl, restarts the service. Confirm via SELECT * FROM activity_logs WHERE message LIKE '[SOFTWARE UPDATE]%' ORDER BY id DESC or the desktop Load logs.

D — Dashboard (reviewer PCs only, 1–2 people)

Copy SecureDeviceControl-Dashboard.zip, run the single EXE, create Admin ID/password, Settings → paste URL + service_role → Save → Refresh. Devices list live from registered_devices; snapshots grouped by device → date → deduped sessions. Self-check anytime: SecureDeviceControl.Dashboard.exe --selftest (7/7).

FAQ

“The operation has timed out” on register?

Desktop’s IpcClient (8 s) reached a service/pipe that wasn’t ready. Install elevated first, wait for STATE: 4 RUNNING, confirm \\.\pipe\SecureDeviceControl.v1 exists, launch the installed desktop — then register.

ENOTFOUND tenant/user — is my DB password wrong?

No. Wrong password says password authentication failed. ENOTFOUND means Host/Username mismatch. Use the exact Transaction/Session pooler host from Database → Connect (aws-1-ap-south-1, not aws-0), and Session 5432 for the service.

Snapshots stopped at 2:10 — why?

You closed the window, which disposed the capture loop. Since 1.0.2, X hides to tray instead; keep the shield icon running or autostart --snapshot-agent at logon.

PC off / reboot — what resumes?

Service is Automatic and resumes alone. Desktop capture resumes at next user logon via HKCU\…\Run\SecureDeviceControlDesktop. No capture happens while logged out.

Dashboard shows no devices though the API has 4?

That was the snake_case JSON bug (fixed in the current EXE) plus pasting the full .../storage/.../rest/... URL into the URL field. Paste only the base https://…supabase.co, use the rebuilt EXE, press Refresh.

Why not Supabase / Drive for the 98 MB update?

Supabase caps objects at 50 MB (413). Drive serves a virus-scan HTML page that fails SHA256. GitHub Releases allows 2 GB direct downloads — that’s the update host.

Why did private repo break updates?

The updater sends no auth token, so private assets return 404. Keep code private if you like, but update ZIPs must live on a public URL (separate releases repo or public host).

Do I need the target PC for updates?

Only once (first install, and the single 1.0.0→1.0.2 jump). After that, software_updates rows apply themselves hourly with no RDP and no open window.

Uninstall before updating?

Never for updates. Overwrite in place; the DB (PINs, email, logs) survives. Uninstall wipes registration.

How do I stop snapshots / change the interval?

Per PC: close tray via Exit, or set local snapshot_enabled=false. Interval: UPDATE device_policies SET snapshot_interval_minutes=15 … (1–120, clamped) — syncs in ~30 s. This fleet is on 15 min.

Are google.com + chatgpt.com a full whitelist?

No. Hosts-file filtering blocks known distracting/mail/VPN domains; it cannot block “everything else”. For a true allow-list add Defender Firewall or proxy rules.

Why did the Windows password disappear from the table?

Old code cleared it on COMPLETED. 1.0.3 keeps it visible. Existing id=1 PENDING TestUser was already visible; completed rows now stay readable too.

Two service names?

SecureDeviceControl (correct, Program Files) vs Secure Device Control (legacy dev path). Re-run install with -MigrateLegacyService.

Hide vs lock a folder?

Shipped: HIDE_FOLDER/UNHIDE_FOLDER (Hidden+System, reversible, service keeps running). Deny-delete ACL locking was offered but not applied — say the word and it ships as LOCK_FOLDER in 1.0.4.
