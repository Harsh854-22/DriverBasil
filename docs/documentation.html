Windows 10 and Windows 11

Local hardware control that installs predictably.

A two-PIN Windows Service for USB-storage and mobile-device control. This guide is written for both office administrators and the people who support the PCs.

Start Here

No API key is required for local device protection. The packaged desktop and service are self-contained. The administrator installs the service once, then the desktop app communicates only through the local Windows service.

Package contents

  • SecureDeviceControl.Desktop.exe: administrator interface.
  • SecureDeviceControl.Service.exe: privileged Windows Service.
  • install-service.ps1: approved installation and repair script.
  • Install-Service.cmd: convenience launcher for the installer.
  • uninstall-service.ps1: PIN-authorized removal script.

Before deploying to 50 PCs

  • Test the package on two representative non-production PCs.
  • Use a Windows administrator account for installation.
  • Give ordinary employees standard-user accounts, not local administrator rights.
  • Create different, non-reused six-digit PINs for each PC.
Important: the legacy package contained a direct cloud database credential. Rotate that credential in the provider dashboard and discard every old ZIP or extracted copy. The corrected release does not package a cloud credential.

Install And Repair

The desktop application does not create a Windows service or request elevated access itself. This is intentional: service installation is an explicit, auditable administrator action.

Normal installation

  1. Extract SecureDeviceControl-Release.zip to a local folder.
  2. Open PowerShell with Run as administrator.
  3. Run the following commands from the extracted folder.
Set-Location "C:\Path\To\SecureDeviceControl-Release"
Unblock-File -Path .\*
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-service.ps1
sc.exe query SecureDeviceControl

The expected result is STATE : 4 RUNNING. The installed service runs as LocalSystem and its binary is copied into C:\Program Files\SecureDeviceControl.

Repair this specific startup failure

Use this only when Event Viewer reports SQLite Error 14: unable to open database file, or when the old package created both SecureDeviceControl and Secure Device Control.

Set-Location "C:\Path\To\SecureDeviceControl-Release"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-service.ps1 -MigrateLegacyService -ResetLocalData
sc.exe query SecureDeviceControl
What repair changes: it removes only the obsolete duplicate service and moves existing secure-device-control.db, -wal, and -shm files into a timestamped C:\ProgramData\SecureDeviceControl\recovery folder. It does not delete them. You will need to create the two PINs again after a reset.

Validate the installation

Get-Service SecureDeviceControl | Format-List Name,Status,StartType,DisplayName
sc.exe qc SecureDeviceControl
Get-WinEvent -FilterHashtable @{ LogName = "Application"; StartTime = (Get-Date).AddMinutes(-10) } |
  Where-Object { $_.Message -match "SecureDeviceControl|SQLite Error" } |
  Select-Object TimeCreated, Id, LevelDisplayName, Message |
  Format-List

Daily Workflow

Windows administratorInstalls or repairs the service with UAC approval.The device policy service starts automatically at boot.

Use the two PINs correctly

  • Device Unlock PIN: permits pendrive/mobile unlock actions. Use six digits and do not reuse it as the uninstall PIN.
  • Uninstall PIN: creates a short-lived removal authorization. Store it separately from the Device Unlock PIN.
  • Do not use example PINs, staff birthdays, or one company-wide PIN.

Permissions And Security

What receives privilege

Only SecureDeviceControl runs with LocalSystem rights. It owns registry policy changes and local audit storage. The desktop app has no code path that creates, stops, or changes the service.

Protected locations

C:\Program Files\SecureDeviceControl and C:\ProgramData\SecureDeviceControl grant full control to SYSTEM and local Administrators. Standard users do not receive write access.

  • PINs use Argon2id hashes and DPAPI-protected records.
  • PIN attempts are rate-limited after repeated invalid entries.
  • Service restarts are configured through Windows Service Control Manager recovery actions.
  • Windows administrators can still disable or remove third-party software. This product resists standard-user bypasses; it does not claim to be impossible for an unrestricted administrator to bypass.

Activities And Testing

Use the desktop app's Load logs action after validating the service. Local activity records include service starts, PIN validation events, policy changes, temporary unlocks, and detected removable-drive writes.

Release acceptance test

  1. Install on a test PC using the normal installation commands.
  2. Verify the service is running and the desktop reports Needs Registration.
  3. Set two distinct PINs, attach a test pendrive, and verify it is blocked.
  4. Unlock for 15 minutes with the Device Unlock PIN and verify access.
  5. Restart Windows, then verify the service starts automatically and the policy is restored.
  6. Enter an incorrect PIN five times and verify the temporary lockout.
  7. Use the Uninstall PIN flow only on a disposable test machine.
The automated suite validates policy logic, PIN rules, rate limiting, IPC session checks, and stress loops. It does not replace live hardware, reboot, service-account, or standard-user tests on your actual Windows image.
