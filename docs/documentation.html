Technical Deep Dive

Kavach divides operations across two processes to enforce OS-level privilege boundaries.

Privileged Windows Service

The Service (SecureDeviceControl.Service.exe) runs as SYSTEM. It performs all cryptographic validations, hosts the Named Pipe server, and controls the storage driver registry key.

  • Driver Lockout: Every 5 seconds, the service checks the active unlock timer. If inactive, it enforces lock state by writing Start = 4 (disabled) to the registry subkey: 
    HKLM\SYSTEM\CurrentControlSet\Services\USBSTOR
  • SQLite Store: Houses activity logs and credentials under %ProgramData%\SecureDeviceControl, protected by NTFS ACLs allowing access only to SYSTEM and Administrators.

Desktop Interface & IPC

The Desktop UI (SecureDeviceControl.Desktop.exe) runs as WPF in the standard user's session, isolated from drivers.

  • Named Pipe IPC: Communicates with the service over the local named pipe SecureDeviceControl.v1.
  • Pipe ACLs: Restricts control access: 
    SYSTEM & Administrators -> FullControl
Authenticated Users -> Read/Write
  • Strict JSON Schema: Deserialization is configured to disallow unmapped members, stopping buffer overflows and object injections.

Cryptographic Hardening

Passwords are never stored in plaintext or reversible formats. PIN verification uses top-tier cryptography:

  • Argon2id Hashing: PINs are processed using Argon2id with 64 MB Memory, 3 Iterations, and a Degree of Parallelism of 2. An independent 16-byte random salt is generated per password.
  • Constant-Time Verification: To mitigate side-channel timing attacks, hashes are validated using CryptographicOperations.FixedTimeEquals().
  • Memory Safety: PIN byte arrays are zeroed out immediately after hashing using CryptographicOperations.ZeroMemory().
  • At-Rest Encryption: Hashed credentials stored in SQLite are encrypted using Windows DPAPI (Data Protection API) with a LocalMachine scope, bound by system integrity.

Step-by-Step Deployment Guide

Follow these steps to deploy and lock down each of the 50 target workstations.

1

Extract Deployment Package

Copy the generated SecureDeviceControl-Release.zip archive to the target workstation. It is recommended to extract it to a directory such as C:\Program Files\SecureDeviceControl.

# Extracted flat folder structure:
# \SecureDeviceControl.Service.exe  <- High-privilege Background Service
# \SecureDeviceControl.Desktop.exe  <- User-level Administrator GUI
# \install-service.ps1              <- Install helper script (flat)
# \uninstall-service.ps1            <- Token-based removal script (flat)
2

Install & Register the Windows Service

Open an elevated PowerShell session (Run as Administrator) inside the extracted directory. If you are on a standard user account, Windows UAC will prompt you for your Windows Administrator credentials.

Run the installation script directly from the folder:

Set-ExecutionPolicy Bypass -Scope Process -Force
.\install-service.ps1

This script sets directory permissions to SYSTEM and Administrators only, creates the service SecureDeviceControl, configures it to run under the local SYSTEM context with Automatic startup, and starts it.

3

Launch Desktop App & Set PINs

Launch SecureDeviceControl.Desktop.exe. Because the database has no PIN credentials, the app will display the **First-run PIN setup** screen.

Enter two different 6-digit PINs:

  1. Pendrive Access PIN: Used by the admin or power users to unlock USB ports for a 15-minute window.
  2. Uninstall / Modify PIN: Used only when changing the service configuration, generating uninstall authorization, or removing the software.

Click Initialize protection. The service will hash the PINs, store them securely in the database, and immediately apply the lock policy to the USB ports.

4

Workstation Lockout Active

The PC is now secure. If anyone plugs in an unauthorized removable drive, Windows will deny driver initialization, preventing the drive from showing up or transmitting files.

Preventing Policy Bypasses (Station Hardening)

Kavach effectively locks down direct USB mass storage access. However, determined users can use alternative vectors to exfiltrate files. Follow these steps to secure all bypass vectors on the 50 PCs.

1

Block Smartphones and Cameras (MTP/PTP Devices)

Smartphones and tablets use WPD (Windows Portable Devices) driver stacks instead of standard USBSTOR, bypassing mass storage locks.

Step-by-Step Mitigation:

  1. Press Win + R, type gpedit.msc, and hit Enter to open the Local Group Policy Editor.
  2. Navigate to: Computer Configuration -> Administrative Templates -> System -> Removable Storage Access.
  3. Locate "WPD Devices: Deny read access", double-click it, set it to Enabled, and click OK.
  4. Locate "WPD Devices: Deny write access", double-click it, set it to Enabled, and click OK.
2

Prevent Boot-Time Operating System Bypass (BIOS/UEFI Lock)

Users can reboot the workstation into a Linux Live USB or Windows PE to view the C:\ drive and copy data without Windows policies active.

Step-by-Step Mitigation:

  1. Enable BitLocker: Right-click the local disk (C:) in Explorer and select Turn on BitLocker. This encrypts the drive, making it fully unreadable outside of the authorized Windows environment.
  2. Disable External Booting: Reboot the PC, press the BIOS key (usually F2, F12, or Del), and navigate to the Boot priority menu. Disable USB and CD/DVD booting options.
  3. Set BIOS Password: Create a strong BIOS/UEFI Supervisor Password to prevent users from re-enabling USB booting.
3

Block USB Internet Tethering & Network Adapters

Users can share their phone's mobile network connection via USB tethering to upload files directly to cloud drives, bypassing local firewalls.

Step-by-Step Mitigation:

  1. Disable USB Remote NDIS tethering drivers by running the following commands in an elevated PowerShell session: 
    Disable-PnpDevice -InstanceId (Get-PnpDevice -FriendlyName "*NDIS*").InstanceId -Confirm:$false
  2. Additionally, block access to webmail and cloud storage (Google Drive, Dropbox, Mega) on the network router or DNS level.
4

Restrict Local Administrator Rights

Users with local admin rights can stop the service, rewrite driver keys directly, or clear logs.

Step-by-Step Mitigation:

  1. Ensure all local users are assigned Standard User accounts.
  2. Audit local administrators group by running: 
    net localgroup administrators
  3. Remove non-admin users from the group: 
    net localgroup administrators [username] /delete

Why Kavach is Better than Native GPO / Registry

While Windows provides native methods to block USB ports, they are designed for static environments and carry significant operational and security disadvantages in workstation fleets.

1. Active Enforcement Loop vs. Static Registry

With native Registry locking (USBSTOR = 4), a user who acquires temporary admin credentials can easily change the registry back to 3 to run a USB. There is no active agent running to re-enforce the lock. Kavach runs an active enforcement loop every 5 seconds. If the registry is manually changed, Kavach automatically overwrites it back to locked within 5 seconds, unless a verified PIN-unlock timer is running.

2. Automated Fail-Closed Workflow

Under both Group Policy and Registry locks, to copy a file or install an updates package, an admin must log in, disable the block, copy the file, and then manually re-enable it. If the admin forgets to re-enable it, the PC remains permanently insecure. Kavach's 15-minute timer relocks automatically, removing human error from the lifecycle.

3. Windows Edition Portability

Local Group Policy (gpedit.msc) is blocked on Windows Home. In workstation environments running a mix of Home, Pro, and Enterprise licenses, GPO cannot be used consistently. Kavach runs directly on the .NET runtime, providing identical driver-level enforcement across all editions of Windows.

Disadvantages of Native Methods

Disadvantages of Local Group Policy (GPO):

  • Zero Self-Service: No dynamic bypass capability; requires manual administrative reconfiguration for temporary tasks.
  • Version Lock: Blocked on Windows Home edition.
  • No local tamper logging: Fails to record individual policy violation attempts in a dedicated database.

Disadvantages of Registry Locking:

  • Trivial to Bypass: Any process running with administrative context can write a new registry value to unlock USBs permanently.
  • Prone to Human Error: Manual unlocking requires manual relocking. Leaving it unlocked by accident leaves the host vulnerable.
  • Zero Auditing: Toggling registry keys does not log historical admin usage or validation attempts.
